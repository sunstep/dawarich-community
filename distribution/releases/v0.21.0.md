## Highlights

**Dawarich Community 0.21.0 marks a major milestone for background location tracking.** The tracking system has been rewritten around Tracelet, with a strong focus on foreground service reliability, recovery, and more consistent tracking when the app is not open.

This release also brings improvements to the timeline, batch uploads, onboarding, and network compatibility.

## What's new

### Tracking and background uploads

- **Tracker rewrite:** Reworked the tracking implementation around Tracelet to improve foreground service stability and background tracking reliability.
- **Auto mode by default:** New installations now default to automatic tracking mode instead of timer mode.
- **Time-based batch uploads:** Added a time trigger for batch uploads, alongside configurable expiration handling for pending batches.

### Timeline

- **Better local and server point integration:** Unsynced local points now connect more naturally to points retrieved from the Dawarich API.
- **Smoother uploads:** Points uploaded in a batch transition into API-backed timeline points instead of disappearing from the map until the next refresh.
- **More complete day boundaries:** The timeline can show the last point from today and the first point from adjacent days for better route continuity.
- **Configurable distance filter:** Added a timeline distance-filter preference in Settings.
- **More efficient initial map location:** The timeline uses the last known location for its initial position rather than requesting a fresh location fix.

### Usability and connectivity

- **Stats cache protection:** Previously cached statistics are retained when a refresh fails, including when the device is offline.
- **QR code login for hosted instances:** The QR scanning option is now available for hosted Dawarich instances ([#572](https://github.com/sunstep/dawarich-community/issues/572)).
- **Optional permissions onboarding:** You can skip the initial permissions screen without granting every permission ([#582](https://github.com/sunstep/dawarich-community/issues/582)).
- **User-installed certificate authorities:** Improved support for servers using self-signed certificates trusted through a user-installed CA.

## Important: Android package name change

The Android application ID has changed as part of the move to **Abra Labs**:

| Variant | Previous application ID | New application ID |
| --- | --- | --- |
| GMS | `com.sunstep.travel` | `dev.abralabs.travel` |
| FOSS | `com.sunstep.travel.foss` | `dev.abralabs.travel.foss` |

**Android treats the new application ID as a separate app, not an update to the old installation.** Your existing local database, settings, and unsynced location points will not automatically transfer to the new app.

Before uninstalling the previous app, **make sure all local location points have been uploaded to your Dawarich server**. Server-side location history remains associated with your Dawarich account or instance.

F-Droid distribution under the new application ID is being handled separately.

## Known issue

- **Timeline location indicator may increase battery use:** The current-location marker can keep requesting high-accuracy location updates while the app is in the background. A fix is planned for a subsequent release ([#701](https://github.com/sunstep/dawarich-community/issues/701)).
